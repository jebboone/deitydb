DEITYDB — SESSION SEED  (current as of v1.56.0, 2026-06-15)
================================================================================
A source-traceable comparative-religion database of spiritual entities (gods,
angels, demons, jinn, aeons, archons, daimones, saints, prophets, imams, heroes,
monsters, cosmological realms, ritual categories, personified abstractions)
across Western/Near-Eastern traditions. It distinguishes entity KINDS rather than
collapsing everything into "gods."

CURRENT SCALE: 1,682 entities · 2,760 relationships · 244 sources · 78 tradition
labels · ~94% of entities backed by a primary text or scholarly edition ·
0 unsourced · 0 unresolved relationship refs · 0 duplicate source-pairs ·
0 unreviewed duplicates. Version 1.56.0.

SCHEMA ESSENTIALS  (schema/bootstrap.sql -> tables.sql, constraints.sql, views.sql)
--------------------------------------------------------------------------------
- entities(entity_id PK, canonical_name, greek_name, tradition, entity_type,
  category, primary_domains, tags, cult_scope, primary_period, evidence_confidence
  CHECK A/B/C/D, review_status, inclusion_basis, earth_association_score 0-5,
  chthonic_flag, serpent_flag, short_note).  Use review_status 'candidate_verified_name'.
- entity_sources(entity_id, source_id, evidence_type, source_note).  PK =
  (entity_id, source_id, evidence_type).  (entity_id,source_id) is value-unique now.
- entity_relationships(subject_entity_id, relationship_type, object_entity_id,
  confidence['high'/'medium'/'low'], rationale, source_id, review_status['reviewed']).
  UNIQUE(subject,type,object). relationship_type FK -> relationship_types.
- entity_periods(entity_id, period_id, confidence['A'..], rationale, source_id,
  review_status).  PK(entity_id,period_id) — many-to-many.
- periods(period_id, tradition, period_name, start_year, end_year, notes) — 71
  periods with integer years (BCE negative). The "Christ event" ~ year 1.
- sources(source_id, title, url, source_type, scope).
- entity_duplicate_review(canonical_name, entity_id, duplicate_group_note,
  decision='intentional_distinct') — register cross-tradition homonyms here.
- v_release_metrics: entities/relationships/sources/tradition_tags(=853 tag rows,
  NOT the 78 distinct traditions)/unreviewed_duplicates/unresolved_relationships.

CONTROLLED VOCABULARIES (keep clean; normalized via scripts, no CHECK constraint):
- source_type (6): 'primary text', 'secondary scholarship', 'reference work',
  'primary inscription/artifact', 'heresiological source', 'internal'.
- evidence_type (5): 'direct attestation', 'scholarly attestation',
  'index attestation', 'inscriptional attestation', 'probable attestation'.
  USE THESE EXACT STRINGS in new entity_sources rows.

--------------------------------------------------------------------------------
GOTCHAS (learned the hard way — don't repeat)
--------------------------------------------------------------------------------
1. relationship_type 'created_by' DOES NOT EXIST. Use 'creator_of' (subject->object).
   This rolled back two whole transactions. Check relationship_types before using a verb.
2. Cross-tradition HOMONYMS (same canonical_name, different tradition) raise
   v_release_metrics.unreviewed_duplicates. Fix: add BOTH entities to
   entity_duplicate_review (decision 'intentional_distinct'); often also wire a
   reception_of edge. Same-tradition-continuum dups (e.g. Italic vs Roman Faunus)
   should instead be MERGED, not split.
3. ALWAYS add entity_periods links for new entities (earlier passes forgot, leaving
   ~150 undated; v1.51.0 backfilled them). Pick the right period_id from `periods`.
4. evidence_type used to be 25 ad-hoc values that caused duplicate (entity,source)
   pairs (same citation under two spellings). Normalized in v1.50.1 — keep using
   the 5 controlled values so ON CONFLICT dedupes correctly.
5. Use ON CONFLICT DO NOTHING on every insert. Verify after every script:
   unsourced / unresolved_rel / dup_pairs / unreviewed_duplicates all = 0.
6. db title / version: metadata.yaml is version-free; VERSION drives the footer.

--------------------------------------------------------------------------------
HOUSE STYLE FOR A CONTENT BUILD-OUT (the repeatable pattern)
--------------------------------------------------------------------------------
One committed script per tradition in scripts/, structured: (a) INSERT new sources;
(b) INSERT entities (full attrs); (c) INSERT entity_sources (each -> its primary
locus, normalized evidence_type); (d) INSERT entity_periods; (e) INSERT
entity_relationships (typed verbs, wire the actual myth/theogony as a graph, not a
flat list); (f) register any homonyms in entity_duplicate_review; (g) verify block.
Then run the publish cycle. Entity-id convention: ENT_<TRAD>_<NAME>
(e.g. ENT_MES_, ENT_NOR_, ENT_ISL_, ENT_JM_, ENT_HTT_, ENT_ORTH_, ENT_HER_, ENT_ZOR_).

METHODOLOGY RULES (enforce):
- Prefer typed relations (patron_of, embodies, opposes, emanates_from, slays,
  child_of, member_of, consort_of, identified_with, reception_of...). Treat
  associated_with as a code smell.
- Every entity needs >=1 source; prioritize PRIMARY texts / scholarly editions.
  NEVER fabricate a source or a citation locus. If no clean primary locus exists,
  leave it / flag it rather than invent.
- Humans only if "raised to functional godhood / great cultic esteem" (Mary
  Theotokos, the Imams, deified emperors, great wonderworker-saints). EXCLUDE
  theologians/authors qua authors.
- Don't collapse entity kinds. Keep the strict graph (0 dangling refs).
- Cross-tradition influence is a feature: wire reception_of/syncretized_with edges
  (e.g. Zoroastrian Az -> Manichaean Az; Greek Hecate -> Chaldean Hecate; Gnostic
  Demiurge reception_of the Hermetic/Platonic Demiurge; Aeshma -> Asmodeus theme).
